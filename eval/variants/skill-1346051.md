# Spitballing — boundary sampling

Creativity here is a methodical search, not a muse. Every request defines an
idea-space with two measured axes:

- **Value** — does an idea fulfill the request?
- **Obviousness** — would ≥25% of a blind naive panel spontaneously produce it?

You reject the **positive set** (obvious fulfillments — too easy) and the
**negative set** (doesn't fulfill — off-target), and target the **band**: high
value, low obviousness, hugging the negative border. You run three stages —
MAP, SAMPLE, CONVERGE — and end with a final 3–5.

## Anti-trigger check (do this first)

If the user wants to converge on and refine ONE approach into a design/spec,
that is brainstorming, not this. Say so and offer to switch. Spitballing returns
a *set* (3–5) of measured options; it never picks the single winner for them.

## The brief (frame once, infer & confirm)

Restate the request as a brief; show it, let the user tweak in one pass — no
interrogation:

```json
{"request": "...", "fulfillment_criterion": "what makes an answer COUNT",
 "output_kind": "the shape of one answer", "hard_constraints": ["filters"]}
```

`fulfillment_criterion` defines the value axis — it is exactly what the value
judge tests. `hard_constraints` filter in CONVERGE only, never during sampling.

## Stage 1 — MAP

**Positive set (blind panel).** Spawn **N=12** independent agents with the Task
tool, in parallel, each given ONLY the request and `output_kind` and this
instruction — nothing about each other, nothing about this skill:

> "Give your first 8 instinctive answers to: «request». One per line, no
> explanation."

Pool all answers. *You* cluster them by underlying approach (clustering needs
all answers at once; it needs no independence, so you do it — do NOT ask an
agent). Record, per cluster, the distinct panelists who reached it.

**Cluster granularity — by mechanism, not wording.** Cluster by *how* an answer
fulfills the request (its underlying approach), never by shared words or surface
features. Two answers belong in one cluster iff they're interchangeable in *why*
they work — not because they share a lexeme. Sanity-check the result: if many
clusters all clear the 25% cutoff, you're splitting on surface form — merge them
by mechanism; if everything collapses into one mega-cluster, you're too coarse —
split the distinct approaches back out. Too-fine inflates the obvious set and
over-rejects; too-coarse starves the band.

Then run the kernel to apply the 25% cutoff:

```bash
echo '{"panelists":[{"clusters":["literal","weather"]}, ...]}' \
  | PYTHONPATH="${CLAUDE_PLUGIN_ROOT}" python3 -m tools.spitball obvious
```

Each panelist entry lists the distinct cluster labels that panelist produced.
The returned `obvious_clusters` ARE the positive set.

**Negative fringe (derive, don't guess).** The fringe is the *structured
complement* of `fulfillment_criterion`, not free invention. Procedure:

1. **Decompose** the criterion into the necessary predicates that ALL must hold
   for an answer to count — its conjuncts. ("communicates cooling the head" =
   COOLING ∧ HEAD ∧ literal-not-figurative ∧ cooling-not-mere-comfort.)
2. **Leave one out.** For each predicate, write the landmark that satisfies every
   conjunct EXCEPT that one — the closest miss along that axis. (drop HEAD →
   *evokes cold but not the head*; drop COOLING → *evokes the head but not
   cooling*.)
3. **Sense-swap.** For any predicate with a figurative or polysemous reading,
   add the landmark that uses the wrong sense of the right word ("cool head" =
   composure, not temperature).

Complete relative to the criterion's structure and reproducible — two conductors
decomposing the same criterion land on the same fringe, not on whatever each
happened to imagine. Tag each landmark with the predicate it drops so the map
stays auditable. The landmarks are a compass for SAMPLE, not a filter.

**Write `map.json`** to `docs/spitball/<topic-slug>/map.json`. Augment each
kernel-returned cluster with the `member_ideas` you clustered into it, so the map
records which panel answers formed the obvious set:

```json
{"value_criterion": "...",
 "predicates": ["COOLING", "HEAD", "literal", "cooling-not-comfort"],
 "obvious_clusters": [{"label": "...", "panelist_count": 9, "frac": 0.75,
                       "member_ideas": ["...", "..."]}],
 "negative_fringe": [{"drops": "HEAD", "landmark": "cold, no cranial reference",
                      "examples": ["Glacier", "Frostbite"]}]}
```

**Validate the fringe against the panel (optional).** The derived fringe is a
claim; the pooled panel answers already hold the evidence. Run the same
`value_score` fulfillment judgment CONVERGE uses (0–1 vs. `fulfillment_criterion`
— value only, no `hard_constraints`; those filter candidates, not the fringe
evidence) over the panel's ~N×K pooled answers instead of candidates, keeping
each answer's `panelist` index. At scale this is one judge-agent pass over
answers you already have; blindness does not apply (the value judge is not the
panel).

Keep the answers scoring in the near-miss band — just below the floor
(`fringe-check` defaults to `0.2 ≤ value < 0.6`) — and cluster *those* by which
predicate each relaxes: a fresh clustering, distinct from the obvious clusters.
Tag each near-miss cluster with that predicate as `drops`. Every pooled answer
goes in `answers` with its `panelist` and `value_score`; only near-miss-band
answers carry a `cluster`:

```bash
echo '{"predicates":["COOLING","HEAD"],
       "answers":[{"panelist":0,"value_score":0.9},
                  {"panelist":3,"value_score":0.4,"cluster":"cold-not-cranial"}],
       "clusters":[{"label":"cold-not-cranial","drops":"HEAD"}]}' \
  | PYTHONPATH="${CLAUDE_PLUGIN_ROOT}" python3 -m tools.spitball fringe-check
```

Read `unmatched`: each label is a near-miss the panel produced along an axis your
`predicates` don't name — a hole in the decomposition. Add the missing predicate,
re-derive its landmark, rewrite `map.json`. One-directional on purpose: a label
in `unmatched` is evidence, but a predicate with no near-miss is not (instinctive
panels skew on-target, so absence is sampling sparsity). Skip for quick runs; use
it when the fringe must bite.

## Stage 2 — SAMPLE

Generate ~40 candidates aimed at the band. Give generation the full compass:
the request + `fulfillment_criterion`, the **positive set** ("these are taken /
obvious — go *outside* them"), and the **negative fringe** ("the productive edge
is just inside here: fulfill the request, but lean toward this failure border").
Sample loosely — no scoring yet. (You may fan out a few Task agents for breadth;
independence is not load-bearing here.)

## Stage 3 — CONVERGE

For each candidate, supply the two semantic judgments yourself (or via a judge
agent at scale):

- `nearest_obvious_cluster`: the obvious-cluster label this candidate falls into,
  or `null` if it belongs to none. Match against the labels in `map.json` —
  i.e. `obvious_clusters[*].label` (each entry is an object
  `{label, panelist_count, frac}`, not a bare string). **This is the membership
  test — judge it against the map, never by re-polling a fresh panel (that
  reveals the candidate and biases the answer).**
- `value_score` (0–1) vs. `fulfillment_criterion`; apply `hard_constraints` here
  (a violation → treat as not in-band).
- `fringe_proximity` (0–1): closeness to `negative_fringe`.

Write every candidate to `docs/spitball/<topic-slug>/candidates.jsonl`, one
record per line — `{text, value_score, fringe_proximity, nearest_obvious_cluster,
obvious, in_band}`, where `obvious = nearest_obvious_cluster is not null` and
`in_band = value_score >= 0.6 and not obvious`. The two derived flags make the
log auditable: you can see what was cut and why without recomputing. Then let the
kernel filter the band and rank the same candidates:

```bash
echo '{"candidates":[{"text":"Nimbus","value_score":0.8,
  "fringe_proximity":0.7,"nearest_obvious_cluster":null}, ...]}' \
  | PYTHONPATH="${CLAUDE_PLUGIN_ROOT}" python3 -m tools.spitball rank --k 5
```

## Output

Write `docs/spitball/<topic-slug>/result.md`: the final 3–5 (the kernel's
`ranked`), each with one line of rationale (why it fulfills, why it's not
obvious), followed by the map they were measured against. Close with one line:

> "5 band options in `<path>`. Want to take one into brainstorming?"

Never auto-advance to brainstorming.

## Why blindness matters

The panel must be separate agent contexts. One model pretending to be 12
respondents already knows what it "said" — its later picks aren't first
instincts, so the 25% measurement is corrupted. Real independence for the one
measurement that needs it is the whole point of the panel.
